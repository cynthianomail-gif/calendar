# 🌏 全球連假雷達

查全球 121 個國家的國定假日，回答兩件事：

1. **有沒有其他國家正在放連假** —— 代表旅客會湧向你的目的地。
2. **你的目的地自己在不在放假** —— 當地人也在移動，而且有些店會關門。

第二件常常影響更大：日本人在黃金週玩日本，量遠大於外國觀光客。

純靜態網站，手機優先設計，所有計算都在瀏覽器裡完成，**不需要後端、不打任何 API**。
（唯一的外部請求是數字用的 Google Font，載不到就退回系統襯線字型，離線一樣能用。）

## 三個檢視

| 分頁 | 用途 |
| --- | --- |
| **行程檢查** | 輸入出發／回程日與目的地，算出 0–100 的「擁擠指數」、逐日人潮強度、當地營業狀況、期間內正在放假的國家清單，並自動在前後 45 天找出比較不擠的替代日期 |
| **候補日期** | 把考慮中的幾段日期存起來（最多 12 組），依擁擠指數由順到擠排列，一眼比較。每組可一鍵跳到 Google Flights 查價，再把查到的票價記回來，兩筆以上會標出最便宜的。存在瀏覽器裡，關掉再開還在 |
| **月曆** | 整月一眼看完哪幾天全球都在放假。兩種模式：「看當天細節」點日期看有哪些國家在放假；「圈選出發與回程」直接在格子上圈一段日期，當場算出擁擠指數，可加入候補或帶回行程檢查（可跨月圈選） |
| **各國假期** | 依國家查該年度所有假期與 3 天以上連假 |

還可以只比對你在意的國家（依洲別篩選，或一鍵「只看主要客源國」），選擇會記在瀏覽器裡。

**候補日期只存日期區間，不存當時的目的地與篩選**——分數一律用目前設定重算。
所以把目的地從日本改成德國，整份候補清單會跟著重新排名，這正是比較的重點。

## 擁擠指數怎麼算

對行程中的每一天，把「當天正在放假的每個國家」的影響力加總，分成本地與外來兩塊：

```
目的地本身    = 90 × 假期性質 × 連假長度加成 × 2.1
其他國家      = 出境旅遊影響力 × 假期性質 × 連假長度加成 × 地緣親近度
指數          = 100 × (1 − e^(−總影響力 / 250))
```

* **目的地用固定基數 90**，不看它的出境傾向——當地人放假時動的是全體居民，
  跟這個國家愛不愛出國無關。乘上 2.1 是因為本地人潮通常遠大於外國旅客。
* **出境旅遊影響力**：依人口規模與出國旅遊傾向給的相對權重（中國 100、美國 86、日本 82…）。
* **地緣親近度**：同區域 1.0、鄰近區域 0.55、其他 0.25，長程客源大國至少 0.5；
  另有一張表處理眾所皆知的流向（德國→土耳其 0.95、美國→墨西哥 0.95、印度→馬爾地夫 0.95…）。
  巴西放假不會讓京都變擠，這一層就是在處理這件事。
* **假期性質**：春節、黃金週這種「會讓人出國」的假期權重最高，一般紀念日最低。
* **旅遊旺季**（歐洲暑假、日本盂蘭盆節、齋戒月等非法定期間）給固定的溫和權重，
  因為它是整段期間的背景人潮，不是單日尖峰。

行程總分 = 每日平均 × 0.5 + 單日最高 × 0.5（沒指定目的地時是 0.6 / 0.4），
避免「只有一天超擠」被平均掉。指數是**相對參考值**，不是實際旅客人數。

## 為什麼票價是手動記的

即時票價需要 Amadeus、Skyscanner 這類商用 API，而 API 金鑰不能放在前端程式碼裡，
所以一定要有一個後端來代收請求——這個站是純靜態、直接放在 GitHub Pages 上的，沒有後端。

折衷做法是：每組候補日期都能一鍵跳到 Kayak 或 Google Flights 查價，
查到的價格再自己填回來。這樣「擁擠指數」和「實際票價」就能並排比較，
而且不用申請金鑰、不用付費、不用維護伺服器。

**連結一定要用路徑式的結構化網址**，把日期直接寫進 URL：

```
https://www.kayak.com.tw/flights/TPE-TYO/2026-05-16/2026-05-22
https://www.google.com/travel/flights#flt=TPE.TYO.2026-05-16*TYO.TPE.2026-05-22;c:TWD;e:1;sd:1;t:f
```

第一版用的是 Google Flights 的文字查詢（`?q=Flights to Japan on 2026-05-16...`），
但那會被它自己重新解析自然語言，日期常常被忽略，結果只顯示「未來六個月」。

機場用下拉選單挑，顯示成「TPE　台北桃園」。資料裡每個國家都有 `airports` 清單
（全部 121 國、共 456 個機場），抵達機場的選單會依目的地重建，預設是該國主要門戶。
有城市代碼的（TYO、LON、PAR、ROM…）放在第一筆，因為查價時「該城市所有機場」通常才是想要的。

抵達機場的選擇**依國家分別記住**，在幾個目的地之間來回切換不會被覆蓋。

如果之後真的要接**即時**票價，需要多一個 serverless function（Cloudflare Workers、
Vercel 之類）來保管金鑰並代打 API。目前沒走這條，改用下面的「參考價」補上一半。

## 參考價：每天抓一次的趨勢，不是即時報價

`.github/workflows/fares.yml` 每天台灣時間清晨四點跑一次
`scripts/fetch_fares.py`，把「TPE 出發到各國主要門戶」未來六個月的
**每日最低單程價**抓下來，存成 `data/fares/<國碼>.json`，再 commit 回 repo
（資料不在 repo 裡的話，下一次任何人 push 都會把它弄丟）。

前端選了目的地才去載那一國的檔案，首頁載入不受影響。候補清單上
**沒有手動記價的那幾列**會顯示一個灰色的「單程約 $X」，滑上去有完整說明。

三個必須一直記得的限制，前端的文案都照這個寫：

* **是快取價，不是即時報價。** 來源 Travelpayouts 的官方文件自己說資料
  來自快取、建議拿來產生靜態頁面。每筆都帶 `found_at`，顯示時要標出來。
* **是單程價。** 回應裡的 `return_date` 是空字串。不要拿去當來回票價。
* **只從 TPE 出發。** 使用者把出發機場改成別的（例如 KHH），參考價就不顯示——
  換個機場價格根本不一樣，寧可不給。

它也**永遠不覆蓋手動記的票價**：手動記的是真的去查到的，比快取價可信。
「最便宜」那個標籤也只比手動價，混進參考價會讓它失去意義。

### 設定（只需做一次）

1. 到 <https://www.travelpayouts.com/> 註冊聯盟帳號（免費），在
   Tools → API 取得 API token。
2. GitHub repo → Settings → Secrets and variables → Actions → New repository secret，
   名稱 `TRAVELPAYOUTS_TOKEN`，值貼上 token。
3. Actions 分頁 → 「抓機票參考價」→ Run workflow 手動跑一次確認。

沒設定 secret 時 workflow 會直接跳過並留一則 notice，不會失敗、不會每天寄信。

本機測試：

```bash
TRAVELPAYOUTS_TOKEN=xxx python3 scripts/fetch_fares.py --only JP,KR --months 2
```

**幣別還沒實際驗證過**：腳本送的是 `currency=twd`，但沒有 token 就沒辦法確認
API 真的支援台幣。第一次跑完請看一眼數字量級對不對（台北→東京單程幾千到一萬多
才合理），不對的話改用 `--currency usd`，前端顯示的幣別會跟著 JSON 裡的 `currency` 走。

GitHub 對超過 60 天沒有 push 的 repo 會自動停用排程 workflow，
真的長期沒動的話要去 Actions 頁面手動啟用。

## 「擠」跟「有沒有開」是兩件事

以色列的贖罪日人潮極少——因為全國停擺、機場關閉、店家全關。
把這種情況壓進同一個擁擠指數只會得到誤導性的低分，所以營業狀況是**獨立的一條警示**。

每個國家標了一個 `closure` 等級：

| 等級 | 意思 | 例子 |
| --- | --- | --- |
| `open` | 商店與景點大多照常營業 | 日本、台灣、香港、新加坡、泰國 |
| `partial` | 銀行與公家機關休息，觀光區大多照常 | 美國、英國、印度、多數拉美與非洲國家 |
| `strict` | 多數商店、超市與博物館休息 | 德國、奧地利、瑞士、北歐、中東歐、以色列 |

個別假期可以覆寫這個等級：中國與越南的春節、日本的年末年始、印尼的開齋節、
峇里島的靜居日（全島停擺、機場關閉）標為「關門」；日本的黃金週則明確標為
「照常營業，但到處排隊」——這是很多人會誤判的一點。

## 資料

* 涵蓋 121 個國家 × 2026、2027 兩個年度，共約 2300 筆假期。
* 資料由 `scripts/build_holidays.py` 產生：西方與東正教復活節、第 n 個星期幾、
  各國補假規則都用程式算，減少手動輸入的錯誤；農曆、伊斯蘭曆、波斯曆節日以錨點日期表驅動。
* **兩種核對狀態**（資料中的 `verified` 欄位，網站上會標示出來）：
  * **已核對（64 國）** —— 2026 年假期逐一對照各國官方公告或權威來源查證過。
    這一輪查出並修正了 26 項錯誤，包括香港清明補假撞復活節星期一要另外加放、
    台灣 2027 兒童節補假順延、泰國把 12/5 誤標為現任國王生日（實為 7/28）、
    柬埔寨亡人節差了九天等。完整清單見 commit 訊息。
  * **範本產生（57 國）** —— 以「宗教／文化節期骨架 + 國定紀念日」組出來，
    結構經過抽查，涵蓋主要假期，但未逐項查證，可能漏掉地方性或次要的假日。
* 標示「推估」的項目請特別留意：
  * 伊斯蘭曆節日（開齋節、宰牲節、齋戒月）依實際觀月，可能相差 1–2 天。
  * 中國、越南的調休安排每年由政府另行公告，此處是常見模式的估計。
* **訂票前請以各國官方公告的行事曆為準。**

## 視覺

粉調底色 + 髮絲線邊框、幾乎不用陰影。介面色（玫瑰）和資料色（薄荷 → 蜜桃 → 珊瑚的擁擠度色階）
分屬冷暖兩個色系，所以「哪幾天比較擠」是頁面上唯一會跳出來的訊息。
數字用 Fraunces 這款軟襯線字體並開啟等寬數字，中文交給系統字型（避免載入好幾 MB 的 CJK webfont）。
深色模式是暖調的紫黑，不是把淺色反過來。

## 開發

```bash
# 1. 重新產生假期資料（改年份或錨點日期後執行）
python3 scripts/build_holidays.py     # -> data/holidays.json

# 2. 打包成瀏覽器可讀的資料檔與單檔版
python3 scripts/build_site.py         # -> data/holidays.js, dist/index.html

# 3. 本機預覽
python3 -m http.server 8000           # 開 http://localhost:8000
```

直接用瀏覽器開 `index.html`（`file://`）也可以，不需要起 server。

### 檔案結構

```
index.html                 頁面骨架
assets/styles.css          樣式（手機優先、支援深色模式）
assets/app.js              全部邏輯：連假偵測、擁擠指數、三個檢視
data/holidays.json         假期資料（正本）
data/holidays.js           同上，包成 window.HOLIDAY_DATA 供頁面載入
data/fares/<國碼>.json     每日最低單程參考價，由排程抓取（首次跑過才會出現）
data/fares/index.json      哪幾國有票價資料，前端據此決定要不要去載
dist/index.html            全部內嵌的單檔版，可直接傳給別人或離線使用
dist/artifact.html         同上但不含 html/head/body 外殼，給自帶外層的環境用
scripts/build_holidays.py  假期資料產生器
scripts/build_site.py      打包腳本
scripts/fetch_fares.py     票價抓取（需要 TRAVELPAYOUTS_TOKEN）
```

`dist/` 那兩個單檔版**沒有**參考價：它們用 `file://` 打開，`fetch` 讀不到
外部 JSON，程式會靜靜降級成只有手動記價。

### 加國家

`scripts/build_holidays.py` 裡有兩種寫法：

* `SIMPLE` —— 大多數國家用這個。挑一個範本（`west_cath` / `west_prot` / `orthodox` /
  `muslim` / `latin` / `anglo` / `persian`），列出國定紀念日，需要時再補幾個計算型節日。
* `@country("XX")` —— 假期結構特殊的國家（調休、農曆、補假規則）用專屬函式。

兩種都要在 `COUNTRIES` 表加一列，包含權重與 `closure` 等級。

### 加新的一年

編輯 `scripts/build_holidays.py`：把年份加進 `YEARS`，並在 `LUNAR` / `ISLAMIC` 等錨點表補上該年的日期，然後重跑上面兩支腳本即可。

## 部署

**第一次要手動開一次 Pages**（workflow 的 token 沒有建立 Pages 站台的權限）：

1. 到 repo 的 **Settings → Pages**，把 Source 選成 **GitHub Actions**。
2. 到 **Actions** 分頁，重跑一次 `Deploy to GitHub Pages`（或直接推一個 commit）。

之後每次推送到預設分支都會自動重新產生資料並發布，網址是
`https://cynthianomail-gif.github.io/calendar/`。

如果第 1 步找不到 GitHub Actions 選項，通常是 **Settings → Actions → General →
Workflow permissions** 被設成唯讀，改成 **Read and write permissions** 即可。

也可以只把 `dist/index.html` 丟到任何地方（甚至存到手機裡離線開）。
